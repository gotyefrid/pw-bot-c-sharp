# Запуск игры в VMware

Если сервер отвечает «Запрещено запускать игру через виртуальные машины» — он узнаёт VM по диску.
Клиент читает модель и серийник `\\.\PhysicalDrive0` и отправляет их в отчёте. У виртуального диска
VMware они выдают себя: модель `VMware Virtual NVMe Disk` / `VMware Virtual SCSI Hard Drive`,
серийник с префиксом `000C29`.

Лечится **настройкой самой виртуалки**, без патча клиента. Проверено 02.11.2026 на VMware Workstation
26.0.1, гость Windows 11 x64: игра заходит в виртуалке на чистом `ElementClient.exe`.

Обновление игры такую виртуалку не ломает — клиент не тронут.

---

## 1. Создание виртуалки

1. **Custom (advanced)** → Next
2. ISO-образ Windows (любой) → Next
3. Название — любое
4. Пароль — любой (запомнить)
5. Прошивка — **UEFI**
6. Number of processors = **1**, Number of cores = **2–4** на выбор
7. Память — на своё усмотрение
8. Next, пока не дойдёте до **I/O Controller Types** → **LSI Logic SAS**
9. **Virtual disk type → SCSI** ← главный шаг
10. Store virtual disk as a **single file**
11. Дальше — по усмотрению

> Выбрали NVMe? Не страшно, скрипт ниже перевесит диск на SCSI. Но проще сразу SCSI.

## 2. Скрипт: сделать диск «обычным»

Скрипт — [`docs/vm-storage.py`](vm-storage.py). Нужен Python 3, больше ничего.

**Виртуалку не запускать.** VMware Workstation можно оставить открытым, но VM должна быть выключена —
скрипт сам проверит и откажется работать.

1. В списке VM: **ПКМ → Open VM directory**
2. Скопировать путь до файла **`.vmx`**
3. В PowerShell:

```powershell
python -I vm-storage.py "C:\Users\ВЫ\Documents\Virtual Machines\Новая VM\Новая VM.vmx"
```

4. Дождаться «Готово» — скрипт сам сделает бэкап `.vmx.bak-storage`
5. Включить VM и установить Windows

### Что делает скрипт

| что | как |
|---|---|
| серийник | `ddb.uuid` в дескрипторе `.vmdk` → `50 00 C5 00 …` (Seagate) |
| модель | `scsi0:0.productID = "ST1000DM010-2EP1"`, `scsi0:0.vendorID = "ATA"` |
| контроллер | `scsi0.virtualDev = "lsisas1068"` |
| серийник включён | `disk.EnableUUID = "TRUE"` — без него SCSI-диск отдаёт пустой серийник |
| NVMe | убирает `nvme*` из `.vmx` |

Читает только первые 64 КБ `.vmdk` (там дескриптор) — сам диск может быть в десятки гигабайт.

### Ключи

```
--model ИМЯ      другая модель диска (ST2000DM008-2FR1)
--keep-uuid      не менять серийник, только модель
--dry-run        показать, что будет сделано, ничего не записать
```

### Проверка

В гостевой Windows, PowerShell:

```powershell
Get-PhysicalDisk | Format-Table DeviceId, FriendlyName, Model, SerialNumber, BusType -AutoSize
```

Должен быть **один** диск: `BusType = SAS`, `Model = ST1000DM010-2EP1`, `SerialNumber`
начинается с `5000c500`. Дальше — VMware Tools и всё остальное.

## 3. Если виртуалка уже есть

1. В гостевой Windows проверить драйвер:
   ```powershell
   reg query HKLM\SYSTEM\CurrentControlSet\Services\LSI_SAS /v Start
   ```
   Должно быть `0x0`.
2. Выключить VM, закрыть VMware.
3. Прогнать скрипт по `.vmx`.
4. Включить, проверить `Get-PhysicalDisk`.

Если драйвера `LSI_SAS` нет — Windows после смены контроллера не загрузится. Откат: вернуть
`.vmx.bak-storage` на место.

## Что важно знать

- **Модель и серийник — от одного производителя.** `ST1000DM010-2EP1` — Seagate, и префикс
  `50 00 C5 00` даёт серийник `5000c5…`, тоже Seagate. Не смешивать марки.
- **Серийник у каждой VM может быть свой** — серверу важно, что он не VMware-шный.
- **`productID` обрезается до 16 символов** — такое поле у SCSI-диска.
- **BitLocker:** если в госте шифрование с привязкой к TPM, смена контроллера у готовой VM может
  потребовать ключ восстановления. Сохранить заранее.
- **Обновление VMware** конфигурацию не ломает — ключи лежат в `.vmx`.
